# AEM Cloudflare worker with personalization

Generated by the `personalize` skill (aem-eds-personalization plugin). It is the official
[adobe/aem-cloudflare-prod-worker](https://github.com/adobe/aem-cloudflare-prod-worker)
(`src/aem-worker.mjs`, unchanged, Apache-2.0) wrapped by `src/index.mjs`, which:

- decides personalized sections (Section Metadata, sources `rules`, `api` and `split`)
  with the same modules as the browser runtime: the section's content becomes the
  variant fragment's content (fetched from the origin as `.plain.html`) and the
  section is marked `data-pzn-source="edge"`, so the browser shows it without
  hiding or deciding it again; `target` sections stay in the browser;
- assigns `split` sections once per browser session (`pzn-split` session cookie);
- leaves sections with browser-only criteria (device, state, audience)
  to the browser;
- serves crawlers the authored (default) content;
- proxies `POST /pzn/decide` to the decision engine with the `PZN_API_KEY` secret.

The origin fetch and its cache key are unchanged; personalized responses are sent
with `Cache-Control: private, no-cache`.

| File | Owner |
|---|---|
| `src/aem-worker.mjs` | Adobe. Re-vendor to upgrade, do not edit |
| `src/personalization/{rules,section-spec,contract,context,provider-api}.js`, `src/personalization/sources/{api,split}.js` | Copied from `scripts/personalization/`. Re-run install-edge after changing them |
| `src/personalization/{personalize,html}.js` | Skill runtime |
| `src/personalization/edge-config.js` | Site |

## Local test

The upstream worker only accepts an `https://main--*--*.aem.live` origin, so run
the dev server over https:

```bash
npx wrangler dev --local-protocol https
curl -sk -D - -o /dev/null https://localhost:8787/        # pages without personalized sections: origin headers, no x-pzn
curl -sk -XPOST https://localhost:8787/pzn/decide -d '{}' # 503 until PZN_API_ENDPOINT is set
```

Pages with personalized sections are only on the origin once their content is published.
Before that, run the edge logic over the preview HTML with the skill's simulator,
which fakes `request.cf` and the user agent:

```bash
node <skill>/scripts/simulate.mjs https://main--<repo>--<owner>.aem.page/<page> --edge --country IN
node <skill>/scripts/simulate.mjs https://main--<repo>--<owner>.aem.page/<page> --edge --ua Googlebot
```

## Deploy

Deploying is the site owner's decision. See the launch checklist in the skill output.

```bash
npx wrangler secret put PZN_API_KEY      # only if a decision engine is used
npx wrangler deploy
```
